Первые шаги к Simple Architecture

00:00 Введение в курс

• Приветствие и анонс онлайн-буткемпа Simple Architecture.
• Обещание показать архитектурный подход, используемый автором более семи лет.
• Упоминание о простых правилах и домашних заданиях для закрепления материала.

00:37 Обнуление и начало курса

• Предложение отбросить предыдущий опыт и видение структуры проекта.
• Начало курса с блока истории и принципов архитектуры.

01:34 История создания архитектуры

• Желание структурировать код с самого начала карьеры программиста.
• Опыт работы над сложным проектом мессенджера-аналога Telegram.
• Проблемы с проектом: сложность и неопытность команды.

03:24 Влияние книги «Чистая архитектура»

• Покупка книги «Чистая архитектура» и её влияние на формирование архитектуры.
• Вывод о универсальности правил хорошей архитектуры.

05:14 Цели архитектуры

• Цель архитектуры: уменьшение человеческих трудозатрат на создание и сопровождение системы.
• Важность простоты добавления новых функций и их доработки в будущем.

06:46 Адаптация принципов Viper

• Поиск примеров адаптации принципов «Чистой архитектуры» в React.
• Знакомство с архитектурой Viper, адаптированной iOS-разработчиками.

08:20 Разбор компонентов Viper

• Объяснение компонентов View и Presenter в контексте React.
• Пример компонента autocomplete для демонстрации работы Presenter.

10:37 Применение архитектуры

• Идея применения хорошей архитектуры для улучшения кода.
• Возможность переписать компонент или сделать текущий код более понятным.

10:40 Прослойка View и Presenter

• Прослойка View — это JSX, который отображает данные.
• Прослойка Presenter содержит JS-логику для извлечения и формирования данных.
• Для отделения логики Presenter создаётся хук usePresenter.

11:37 Правило архитектуры

• Все компоненты являются View-слоем и не содержат JS-логики, кроме импорта usePresenter.
• Простое правило легко объяснить и запомнить.

12:15 Файловая структура

• Папка Autocomplete содержит файлы view.jsx, styles.module.css и usePresenter.js.
• Файл styles.module.css использует CSS modules без препроцессоров.

13:13 Варианты имён файлов

• Первый вариант: index.jsx удобен как точка входа, но все компоненты имеют одно и то же название.
• Второй вариант: имя файла идентично имени папки, например, autocomplete.jsx.
• Выбор между вариантами зависит от предпочтений команды.

15:09 Разделение кода в Presenter

• Код в usePresenter можно разделить на несколько хуков для улучшения читаемости.
• Разделение кода на мелкие файлы упрощает поддержку и добавление новых функций.

16:59 Проблемы с большими файлами

• Большие файлы легко писать, но сложно поддерживать и расширять.
• Пример проблемы: race condition в автокомплете фильмов.
• Добавление новых функций требует разделения кода на файлы.

19:35 Эксперимент с ESLint

• Добавление правила ESLint, запрещающего более 120 строк кода в одном файле, мотивировало разработчиков разбивать код на мелкие файлы.
• Среднее количество файлов увеличилось, разработчики стали писать код лучше.

20:32 Личный опыт

• Автор предпочитает писать маленькие файлы, поэтому правило ESLint не создало для него сложностей.

20:47 Введение в древовидную архитектуру

• Компонент, хуки и функция валидации находятся в одной папке.
• Древовидная архитектура позволяет упорядочить код.
• Каждый компонент имеет свою папку с view и presenter слоями.

21:43 Пример вложенности компонентов

• Пример с мессенджером: мессенджер разбивается на список чатов и активный чат.
• Активный чат включает нижнюю панель с иконкой открытия блока с эмодзи и стикерами.
• Структура папок отражает логику интерфейса.

22:42 Поиск компонентов в древовидной архитектуре

• Пример поиска компонента Sticker Context Menu: начинается с компонента Messenger, затем Chats, Active Chat, Bottom Panel, Sticker Pack Icon, Sticker Pack Popover, Stikers.
• Файловая структура отражает интерфейс браузера.

23:41 Переиспользуемые компоненты

• Переиспользуемые компоненты помещаются в глобальную папку Components.
• Для компонентов, используемых только в определённой части дерева, создаётся папка Components на этом уровне.

24:34 Преимущества промежуточной папки Components

• Промежуточная папка Components удобна при переписывании активного чата.
• Папка Components включает только переиспользуемые компоненты, используемые ниже по дереву.

28:23 Заключение и домашнее задание

• Simple архитектура вдохновлена книгой «Чистая архитектура» и iOS архитектурой Viper.
• Компоненты содержат только JSX и хук usePresenter, остальное — в presenter слое.
• Домашнее задание поможет закрепить знания на практике.
