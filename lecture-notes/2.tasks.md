Структура папок в Simple Architecture
Исходная папка Logic содержит презентеры и таски. Для лучшей организации её разделили на два слоя:

Presenter — слой представления;
Tasks — слой бизнес‑логики.
Внутри папки Logic создали отдельную папку Tasks. Это даёт гибкость в организации кода:

Таску можно оформить одним файлом — если логика простая и укладывается в 120 строк кода.
Таску можно разбить на несколько файлов в отдельной папке — если логика сложная. Лимит в 120 строк — не жёсткое правило, а рекомендация для повышения читаемости кода.
Где хранить таски
Место хранения зависит от типа таски:

Переиспользуемые таски (используются в разных компонентах):

хранятся в глобальной папке Tasks;
доступны для всего приложения;
позволяют избежать дублирования кода.
Одноразовые таски (используются только в одном компоненте):

хранятся в папке Logic внутри конкретного компонента;
привязаны к логике одного компонента;
не требуют глобальной доступности.
Ключевые принципы Simple Architecture
Бизнес‑правила описывают, как бизнес зарабатывает. Они:

могут существовать вне приложения (как отдельные документы или процессы);
реализуются в приложении через бизнес‑логику.
Бизнес‑логика (варианты использования) в Simple Architecture хранится в папке Tasks.

Task — это обычная JS‑функция, при именовании которой:

имя всегда начинается с глагола (например, fetchUser, updateProfile, deleteItem);
название отражает действие, которое выполняет функция.
Работа со сторами:

прямое взаимодействие со сторами без посредников;
исключается использование библиотек типа Redux, Redux Saga, Funk и т. п.;
сторы предоставляют API для прямого доступа к данным.
Независимость от React:

в тасках нет упоминаний React;
слой бизнес‑логики полностью отделён от слоя отображения;
таски можно использовать с другими библиотеками/фреймворками.
Структура компонента:

компонент может содержать папку Logic;
внутри Logic располагаются:
хуки компонента;
папка Tasks (если у компонента есть таски).
Глобальная папка Tasks:

централизованное хранилище переиспользуемых тасок;
обеспечивает единый доступ к общей бизнес‑логике;
упрощает поддержку и обновление повторяющихся операций.
Преимущества соблюдения правил
Если следовать описанным принципам, вы получите:

Чёткое разделение слоёв приложения (бизнес‑логика, представление, данные).
Понимание зависимостей между слоями (какой слой от какого зависит).
Упрощение поддержки кода за счёт стандартизации структуры.
Возможность переиспользования тасок в разных частях приложения.
Независимость бизнес‑логики от UI‑библиотек (можно менять React на что‑то другое без переписывания тасок).
Повышение читаемости кода благодаря ограничению в 120 строк и чёткой структуре папок.

Что такое таск (Task)
Таск в Simple Architecture — это JS‑функция, реализующая конкретный бизнес‑процесс (вариант использования). Она:

всегда называется глаголом (описывает действие);
не зависит от React и других UI‑библиотек;
напрямую работает со сторами (без посредников вроде Redux);
может быть переиспользуемой или одноразовой.
Ключевые признаки таска
Именование через глагол:

fetchUser — получить данные пользователя;
updateProfile — обновить профиль;
deleteItem — удалить элемент;
calculateTotal — рассчитать итоговую сумму;
sendNotification — отправить уведомление.
Работа со сторами напрямую: функция обращается к сторам (хранилищам данных) без использования Redux, Redux Saga и т. п.

Отсутствие React‑специфичного кода: в таске нет JSX, хуков React (useState, useEffect и т. д.), ссылок на компоненты.

Фокус на бизнес‑логике: таск реализует правило бизнеса, а не отрисовку интерфейса.

Автономность: таск самодостаточен — он выполняет одно действие и может быть вызван из любого компонента.

Примеры тасков
Пример 1. Получение данных пользователя (fetchUser)
javascript
// tasks/fetchUser.js
export const fetchUser = async (userId) => {
const user = await userStore.getById(userId);
if (!user) {
throw new Error('Пользователь не найден');
}
return user;
};
Что делает: запрашивает данные пользователя из userStore по ID. Где может использоваться: в профиле пользователя, в админ‑панели, в чате. Тип: переиспользуемый таск.

Пример 2. Обновление профиля (updateProfile)
javascript
// tasks/updateProfile.js
export const updateProfile = async (profileData) => {
// Валидация данных
if (!profileData.name || !profileData.email) {
throw new Error('Заполните обязательные поля');
}

// Обновление в сторе
await userStore.update(profileData);

// Логирование действия
analytics.track('profile_updated', { userId: profileData.id });

return { success: true };
};
Что делает: обновляет данные профиля в userStore, проверяет валидность данных, отправляет событие в аналитику. Где может использоваться: форма редактирования профиля. Тип: переиспользуемый таск.

Пример 3. Расчёт итоговой суммы корзины (calculateCartTotal)
javascript
// tasks/calculateCartTotal.js
export const calculateCartTotal = (items) => {
const subtotal = items.reduce((sum, item) => sum + item.price * item.quantity, 0);
const tax = subtotal * 0.2; // НДС 20%
const total = subtotal + tax;

return {
subtotal: Number(subtotal.toFixed(2)),
tax: Number(tax.toFixed(2)),
total: Number(total.toFixed(2))
};
};
Что делает: считает промежуточную сумму, налог и итоговую стоимость корзины. Где может использоваться: страница корзины, страница оформления заказа. Тип: переиспользуемый таск.

Пример 4. Одноразовый таск для компонента «Виджет погоды»
javascript
// components/WeatherWidget/logic/tasks/fetchWeather.js
export const fetchWeather = async (city) => {
const response = await weatherApi.get(city);
return formatWeatherData(response.data);
};
Что делает: получает данные о погоде для указанного города и форматирует их. Где используется: только внутри компонента WeatherWidget. Тип: одноразовый таск (хранится в Logic компонента).

Пример 5. Отправка уведомления (sendNotification)
javascript
// tasks/sendNotification.js
export const sendNotification = async ({ userId, message, type }) => {
// Проверка прав пользователя
const isAllowed = await notificationStore.checkPermissions(userId, type);
if (!isAllowed) {
throw new Error('Уведомления этого типа запрещены');
}

// Отправка через сервис уведомлений
await notificationService.send({ userId, message, type });

// Запись в лог
log.info(`Уведомление отправлено: ${type} для пользователя ${userId}`);

return { sent: true };
};
Что делает: проверяет разрешения, отправляет уведомление, логирует действие. Где может использоваться: при регистрации, при завершении заказа, при упоминании в чате. Тип: переиспользуемый таск.

Где хранятся таски
Переиспользуемые: в глобальной папке Tasks (например, src/tasks/). Доступны всему приложению.
Одноразовые: в папке Logic конкретного компонента (например, components/MyComponent/logic/tasks/). Используются только внутри этого компонента.
